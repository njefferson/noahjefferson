# The short page

This page is what a worker or a checker reads first. It is short on purpose.

## What is wanted from a session

- Do what was asked and nothing more. A correction narrows the work.
- Say what a long run will cost before it starts. The owner's credit goes to judgement only, so the cheapest tier that holds the rules does the work.
- Report what changed and what it means, in plain words, with the state at the end: finished, paused on what, or running what.
- Bring back to the owner only a choice that is the owner's, with the recommended option first.
- A question from the owner gets an answer and nothing else. The approved plan stands as written. A plan is changed only for a reason, the change is called a change, and it is written in full and approved before any work is done under it.
- When work stops on something only the owner can do, say so as a need: that work is stopped, what is needed and where it is done, why, what it holds up, and what is not known. A need is never written as a choice. A choice is offered only where each option leaves the work whole and the record cannot rank them.
- A question about how sessions are started or run is answered from the hub's `plans/native/running.md`, in whatever repository it is asked.
- Where a repository's own instruction file still describes the gates retired on 12 November 2026, say so once at the start and name the move procedure, the hub's `plans/native/skills/app-move/SKILL.md`. Start it when asked.

## How a piece of work goes

The session scopes the work on one page with five parts, and the owner approves it once.

1. The result, as something that can be seen: a file, a page, a running thing, a number.
2. How it is checked: who opens the real output, and against what.
3. The steps, in a few lines, each small enough for one worker.
4. The cost: how many agents, on which tier, and about how long.
5. The way back: what removes the work if it goes wrong.

Workers on the cheapest tier do the steps. A checker that did none of the work then opens the real output and judges it against the stated result, and nothing is pushed until it has passed the exact commit. The owner gets the result and what the check showed.

## The never-rules

- Nothing in any file quotes or names the repository's owner, or attributes a message to the owner.
- No chat link, model name or trailer goes in a commit or a pull request.
- Only staging and main reach a remote.
- Every time given to the owner is California time.
- No table or grid where the owner reads.
- Anything meant to be pasted is one fenced block.
- The choice popup is never used.
- A refusal from the harness or a hook is an instruction. Say plainly what was refused, and never work around it.
- A statement of state is read in the same turn, never remembered.
- Start no process you will not manage, and confirm it ended by the resource, not the process list.
- When an input does not clearly belong to the work in front of the session, such as an unfamiliar app, screenshot, link, file or repository, ask in plain text before doing anything at all.
- Only the owner decides what appears on the hub's public pages, so a session adds, removes, proposes or mentions no app there unless the owner has named it.

## The standing rules in full

The rules as they stood before the rebuild of 12 November 2026 are live again in the hub, whole and as written.

- `doctrine/never.md` and `doctrine/hub.md`, the hub's instruction file of 11 November 2026: read both whole at every start and after a compaction, before anything else.
- `doctrine/plans.md`: read whole before a page is scoped.
- `doctrine/apps.md`: read where the work points at one of its sections.
- `agent-rules.md` for a worker, `aim-review.md` for a checker, and `plans/seed-template.md` for the drafting of a page.
- These pages bind as written. Where one names a gate, a hook or a file retired on 12 November 2026, the behaviour it asks of a session still binds. Only the refusal no longer arrives, so nothing stops a session that breaks it.
- Where one of them and this page differ on how a piece of work is scoped and who does its steps, this page holds.
