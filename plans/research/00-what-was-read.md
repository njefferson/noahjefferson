## Appendix: what was read on 16 and 17 November 2026

The harness's documentation, at `https://code.claude.com/docs/en/` and the page named:

- `model-config`. The alias `opusplan` uses the opus alias in plan mode and the sonnet alias otherwise. `ANTHROPIC_DEFAULT_OPUS_MODEL` is the model for opus and for `opusplan` when plan mode is on, and `ANTHROPIC_DEFAULT_SONNET_MODEL` the model for sonnet and for `opusplan` when it is off. A model is set, in order of precedence, by the model command in the session, the launch flag, `ANTHROPIC_MODEL`, the `model` setting, then `ANTHROPIC_DEFAULT_MODEL`. In a cloud session the model command takes its value as an argument. `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, from 100,000 to 1,000,000, sets where a cloud session compacts, and models with a million-token window compact at about 967,000 by default. `CLAUDE_CODE_SUBAGENT_MODEL` is the default model for agents and workflow agents, and with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` the model in a role file is ignored.
- `advisor`. A setting, `advisorModel`, lets the serving model consult a stronger one at points it chooses. Opus or Sonnet with Fable as adviser is an accepted pairing. The adviser reads the whole conversation uncached at each call. Nothing caps or forces its calls. It is marked experimental.
- `prompt-caching`. Each model has its own cache. After a change of model the next request reads the whole conversation with no cache, at the new model's rate. The advice is to pick the model and effort at the top of a session.
- `best-practices`. A rule that must hold every time is a hook, a deny rule or a managed setting, and the instruction file is for guidelines. The enforced set is kept small, and forty is named as a sign that most are preferences. A hook that asks a model to decide is not deterministic. The instruction file is kept short, procedures go in skills, and the work is given a check to run. A cleared or fresh context costs less than a long one.
- `memory`. An instruction file is aimed at under 200 lines. The project's root instruction file is read again from disk and put back after a compaction. Imports load with the file that imports them and save no context.
- `sub-agents`. The `agent` setting starts the main thread as a defined agent with that agent's tools and model, and a prompt of its own replaces the harness's. An agent run as the main thread can list the only agent types it may send. A role file carries its model, tools, effort, compaction window, skills and hooks. Hooks in settings fire for an agent's tool calls.
- `settings` and `settings-reference`. In a cloud session with one repository, the repository's own settings file is read, and settings on the owner's own machine are not. `agent`, `advisorModel`, `model`, `autoCompactWindow`, `hooks` and `permissions.deny` may be set in any settings file.
- `hooks`. A hook before a tool call can refuse it and is told the permission mode and, for an agent, the agent's id and type. A hook on a change of settings can refuse the change. A hook at a stop can hold the turn, and after eight holds in a row the harness ends it. A hook before a change of model can refuse it.
- `cloud-environments`. The harness's proxy for GitHub refuses the deletion of a branch and a push of anything but a branch, and does not limit which branch a push updates; the page says to use GitHub's branch rules for that. A setup script runs as root before the session starts and is skipped when a cached environment exists. Variables and the script can be read by anyone who uses the environment.
- `workflows`. A script can be saved under `.claude/workflows/` and run by name with input. In auto mode the first launch asks and later ones do not. A run takes no input once started, can be relaunched from its saved results, and its agents' tool calls get the session's permission checks.
- A search of the same site: writes under `.claude` are a protected path in every mode, an allow rule does not pre-approve them, and a shell command can still make them.
