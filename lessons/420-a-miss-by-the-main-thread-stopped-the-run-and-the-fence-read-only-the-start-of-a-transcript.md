## 420 · A main-thread call outside the record latched the run, the rules-first check read only the start of an agent's transcript, and a page edited since a failed publish was matched against it; a miss now sets no latch and names what may be used, a check says beforehand what passes, the whole transcript is read, and a publish is keyed by the page's content

**Enforced by:** GATE hub:session-guards.test.mjs — the cases that run the hook with main-thread calls outside the record and read that nothing is latched and what the refusal names, the check command through the hook and on the command line (under a latch, chained, made by an agent, and changing nothing), the rules-first check over a transcript whose first message is past the start window, and the reply guard over a failed publish, an edited page and a failure read back from the transcript, with plants in hook-dispatch.mjs, plan-fence.mjs and reply-guard.mjs for every part whose removal must fail a case

**Recorded 2026-10-20.** Three gates stopped work that no gate was there to stop, on the night of 19 to 20 October. The manager fence refused a main-thread call that was not of the record, the reply guard's own remedy command included, and the refusal set the session's latch, so one miss ended the main thread's route until the owner wrote, though the call changed nothing and no work was at risk (Q-HUB-43). The main thread had no way to learn what passed except to make a call and be refused. The plan fence's rules-first check read only the first 512 KB of an agent's transcript while the harness writes about 400 KB before an agent's first call, so a rules Read made after the first message fell past the window and a review died at its fourth call, on a route the fence's own first refusal had told it to take (Q-HUB-46). And the reply guard named a publish of the status page by its path, so a publish of a page edited since a failed one was matched against the failure, and that refusal latched the main thread and then the running review (Q-HUB-45).

**What is done now.** A refusal of the manager fence for a call that is not of the record, whether a read outside it, a write, a SendUserFile, an Artifact call or any tool or command line the fence does not pass, ends with a mark (`FENCE_NO_LATCH`), says that it sets no latch, lists what the main thread may use, and names the check command; `main` in hook-dispatch.mjs reads the mark and sets no latch. The dispatch gate's and the workflow gate's refusals, returned through the fence, carry no mark and latch as before, as does every refusal of every other guard. `node hook-dispatch.mjs --can <tool> <path or command line>` builds the call the main thread would make, asks the same two functions `main` asks (`managerFence` and `latchStanding`, the latter read only so that it removes nothing), and prints whether each would pass, why, whether a refusal would latch, and which gates it does not ask; it exits 0 whatever it finds. On the main thread the dispatcher passes it as it passes the status command, a latch included, and a line with anything chained to it is not it. `rulesFirst` in plan-fence.mjs keeps the window of the transcript's start as the fast path and reads the whole transcript when the window does not show the Read, for the Read and for an earlier refusal both. `callHash` in reply-guard.mjs keys an Artifact call that names a file by the page and the hash of what the file held at the call; a failure read back from the transcript after the file was edited is keyed `changed-since`, which matches no later call.

**What the check cannot see.** The mark travels in the refusal's text, so a refusal that lost it would latch, which is the safe direction. The check asks the fence and the latch only: the review, rules, reads and judgement gates that hold a step, the report gate, the stop and correction holds, plan mode and the family guards are not asked, and a call it passes can still be refused by another gate. The whole read of a transcript costs a parse of the file on every call of an agent whose rules Read lies past the window. An identical resend of a failed publish after the page was edited is, by design, not a repeat.

**The general form.** A gate that refuses a miss and also ends the run turns every miss into a stop; a refusal that changes nothing should hold nothing, and should say what passes and how to ask. A window over a log is a guess about where the evidence is, and the guess fails the day the log's opening grows. A key that names a thing by where it lives and not by what it holds makes a changed thing look like a repeat.
