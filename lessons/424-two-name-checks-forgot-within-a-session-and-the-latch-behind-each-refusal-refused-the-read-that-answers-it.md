## 424 · Two name checks forgot within a session, one by trimming its ledger and one by reading a bounded tail, and the latch behind each refusal refused the read that answers it, so the plan gate now reads the whole session and the disk, a command line is opened as a shell opens it, a refusal a read answers sets no latch, and a review is stale only for the steps it depends on

**Enforced by:** GATE hub:session-guards.test.mjs — the cases that take a plan through ExitPlanMode with a name a result printed beyond the old tail of sixteen megabytes, a bare file name that exists in the session scratchpad, a held name whose file now exists and a bare file name in a repository the plan's Files names, and refuse a made-up name, a path-shaped name that is not on disk, a held name with no file and a file that exists in another session's scratchpad; that open Bash lines as a shell opens them and refuse the lines that do open a command; that run the dispatcher with the doctrine due, with a plan naming something the session has not seen and with the app's identifier guard refusing the approval call, and read the latch after each; and that feed the review state an Order with an After line, with plants in plan-guard.mjs, reply-guard.mjs, plan-fence.mjs, hook-dispatch.mjs and report.mjs for every part whose removal must fail a case · GATE hub:plan-guard.mjs — the name check, which reads the transcript through a widening tail and the disk, and the check of the After line, both at ExitPlanMode · GATE hub:hook-dispatch.mjs — the latch decision for the doctrine gate, the plan gate's refusal of a name and the identifier guard's refusal of the approval call

**Recorded 2026-10-26.** The approval call of a plan was refused for the bare name of a file in the session scratchpad that a tool result had printed the day before. The plan gate's check of names read the last sixteen megabytes of the transcript, a result printed earlier was not in them, and a file that existed on disk was never looked for, so a name that was plainly real counted as made up. The app's identifier check, a hook of the app and not a hub gate, had forgotten an identifier the same way the day before, by trimming its ledger from the front while three agents read at once. Each of the two refused a value the session had read, and each refusal then latched, so the Read that would have shown the value was refused as well, and the plan waited for the owner's next message. Together they cost the last plan three sends and two owner messages. Two gates built to stop a session from inventing a value had each been given a window onto what the session had read, and each window was shorter than the session.

**What is done now.** Four changes in the hub's guards, each with two cases in the guards' test, one that fails on the old code and one that shows the old refusal still fires, and plants that take each part out.
- The plan gate's name check, `inventedNames` and `heldNames` in plan-guard.mjs. The transcript is read through a tail that widens through 2, 8, 32 and 64 megabytes, a loop in plan-guard.mjs over the reader transcript-tail.mjs already exports, in place of the one tail of sixteen. A name that exists on disk passes with no tool result at all: a bare name resolved against the session scratchpad folder, found the way the plan fence finds its allowance, and against each repository the plan's Files names. The same pass releases a held name once its file exists, since the record held a name until a result printed it after the refusal, and a file written between two approval calls printed nothing.
- The opener, `commandsIn` in reply-guard.mjs, read by the plan fence and the host check. A command line is opened as a shell opens it: text in single quotes is one word and opens nothing, text in double quotes opens a command only at a dollar sign with a parenthesis and at a backtick, and the unquoted operators open one as before. The whole-line scan before it opened a backtick pair inside a quoted commit message as a command and refused the commit (Q-HUB-51). The fence's refusal now names the character the line opened the command at and says to write the text into a file in the scratchpad that the script reads.
- The latch, in hook-dispatch.mjs. The doctrine gate's refusal joins the recall gate's and the page gate's as a refusal that sets no latch, since the Read it names clears it; the plan gate's refusal of the approval call for a name the session has not seen sets none, since a read shows the name; and the dispatcher's own latch decision sets none for a refusal of the approval call that comes from the app's identifier guard, which still refuses and is untouched. Every other refusal latches as before.
- The review's staleness, `reviewState` in report.mjs and `afterProblem` in hook-dispatch.mjs. A plan's Order may carry an After line, groups of the form `N after M M` separated by semicolons. A review is stale when the plan file was written after it began, when a correction is newer, when the step it judged or the step it clears ended after it began, or when a step the cleared step follows by the line did; with no After line any end of a step in Order stales it, as before. The plan gate refuses a line that names a step outside the Order or has a group that is not of the form, and the state reads such a line as no line, which is the strict reading.

**The excuse is the one the doctrine names for a guard.** A check that asks whether a value was seen has to say how far back it looks, and a window is chosen when the transcript is small. The remedy a refusal names is a read, so a latch behind that refusal contradicts it, and the doctrine gate and the recall gate showed the two cases side by side.

**What the change cannot see.** A bare name of a file that lives in a subfolder of the scratchpad, `progress/` for one, is resolved against the scratchpad's root, so it still needs a path or a result that printed it. A transcript longer than 64 megabytes is read through its last 64 only, and the disk is then the witness. The app's identifier guard is untouched: its ledger's three faults, the trim within a session, a path argument that exists on disk and a path with a hex name that exists, are queued in the app's notes. A check of a plan's commit ids against git objects at the approval call was not built, since the hub holds no such check and the app's guard is not the hub's. An After line that names only steps of its Order passes whether or not it is true that those steps are independent.

**The general form.** A gate that refuses a value the session cannot account for has to look at the whole of what the session read and at the thing the value names, and a refusal whose remedy is a read must leave the read open.
