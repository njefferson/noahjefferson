## 197 · A missing input does not leave a blank — it becomes a confident false sentence

**Enforced by:** JUDGEMENT — an empty list and a genuinely empty world are the same value, and no gate can tell them apart from inside the function that renders them. · CHECKLIST who-else-consumes-this — when a new entity is added, list every generator and gate that iterates the entity set, and run each one; the app's own test suites do not cover the files it ships. · CHECKLIST empty-means-unknown — any copy of the form "there is no X here" must be reachable only when something was actually asked and actually answered nothing; if the input never arrived, the sentence has to say that instead.

**Smell:** prose generated from `list.length === 0`. Also: "there are no…",
"none were found", "nothing published here" — every one of them is a claim about
the world derived from the absence of data. Also: adding a new member to a set
the codebase iterates in more places than the feature touches.

An app about four rivers gained a fifth entry — a region rather than a river.
Three baked artefacts were generated by tools that iterate the river list, and
each broke differently. Two broke loudly: a check demanded a centreline the new
entry deliberately does not have, and a tide-station check found it declared
tides with no stations baked. Those were fine. **They failed.**

The third did not fail. The access-lands generator measures distance to a
river's centreline, the new entry had none in that file, so it received an empty
list — and the panel rendered the sentence it renders for an empty list:

*"CDFW publishes no land of its own within twelve kilometres of the Delta."*

There are sixteen such sites. The app had not failed to display something; it
had asserted something false, in its own confident register, about a public
agency's holdings — and it was the one output no test looked at, because every
suite was green throughout. **The suites test the app; the checks test the files
the app ships, and those are different populations.**

**Why this shape is the dangerous one.** A blank section invites the question
"why is this empty". A sentence answers it. The failure mode is not a gap in the
interface but a lie in the copy, and it is generated by exactly the code path
written to be helpful about genuine absences. Any app careful enough to
distinguish "nothing here" from "nothing known" in its prose — which is the
right thing to do — has built the machine that will state the wrong one when an
input goes missing.

**The rule that follows.** A sentence claiming absence must be reachable only
from a query that ran. Where the code cannot tell "asked and got nothing" from
"never asked", it must say the weaker thing. And when a new member joins a set,
the search is not "what does my feature touch" but "what iterates this set" —
generators, checks and gates included, every one of them run before the push.
