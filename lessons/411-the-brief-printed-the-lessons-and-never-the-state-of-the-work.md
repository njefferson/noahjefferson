## 411 · The session brief printed the lessons and the doctrine's drift and never the state of the work, so it prints each repository's STATE.md whole where one exists

**Enforced by:** GATE hub:session-guards.test.mjs — the case that runs the brief over a folder of repositories (the one it is run for, the hub's and every repository beside either that holds a `.git`, each STATE.md printed whole, a repository with none printing nothing, a folder that is not a repository ignored, and one line saying so when none keeps one), with plants that take out the whole-file print, the line for none, the sibling scan, the repository test and the hub's own file

**Recorded 2026-10-19.** A state written in a file and not opened is not known, which is the reason the lessons are printed at the start of a session. The state of the work in a repository, where it stands, what is running and what is owed, had no such place, so a session began without it and asked.

**What is done now.** `session-brief.mjs` prints the `STATE.md` at the root of each repository it can see, whole and never a preview or a count: the repository it is run for, the hub, and every repository beside either that holds a `.git`. A repository with no such file prints nothing of its own, and when none has one the brief says so in one line, so that silence is never read as a search that found nothing. The file is the repository's to write; no repository is made to keep one.

**What the check cannot see.** Whether a repository's file is current. A file that goes stale is the failure the generated pages in this family exist to avoid, and this prints whatever is there.

**The general form.** What a session must know at its start is printed at its start, whole, from the place the repository keeps it.
