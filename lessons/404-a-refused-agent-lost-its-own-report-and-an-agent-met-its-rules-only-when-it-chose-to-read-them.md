## 404 · A refused agent could not write its own report, and an agent met the shared rules only if it chose to read them, so a latched agent now writes its record and an agent's first call is the rules

**Enforced by:** GATE hub:session-guards.test.mjs — the case for a latched agent's own report (its progress note and report, `step-N.txt` and `step-N-report.txt` directly in the scratchpad's progress folder for the step its prompt names, pass the latch; another step's, any other name or folder, another tool, another session's scratchpad and every other call stay refused, and its return passes) and the case for the rules read first (every call of an agent but the Read of the shared rules, its return, its TaskStop and its report refused until its own transcript holds a Read of that file that was not refused, and refused when no transcript of it can be found), each with plants that take one check out and must fail it

**Recorded 2026-10-18.** A refusal inside an agent latches that agent: every later call is refused but its own return. The report an agent writes as it works is the record the next send resumes from, and the latch refused that write too, so an agent stopped at its first refusal could hand back only the text of its return and left its step with no report file. Separately, the rules every agent follows are one file that a plan points at, and an agent is sent only a plan path and a step number, so it met the rules only if it happened to read them; the first rule of the file says its first call is that Read, and nothing enforced it.

**What the gates do now.** In the dispatcher, a latch no longer refuses a subagent's Write, Edit or MultiEdit of a file directly in `progress/` of this session's scratchpad named `step-N.txt` or `step-N-report.txt`, where N is the step its own transcript's first prompt names (`agentReportWrite`); when that transcript cannot be found or names no step, any N passes, and nothing else changes: the agent's other calls are held as before, and its return passes. In the plan fence, an agent's call is refused with RULES FIRST until its own transcript holds a Read of the shared rules file, the live clone's copy or the hub copy's, that was not refused (`rulesFirst`, `rulesWereRead`); the Read itself passes, and so do its return, its TaskStop and its report write, so an agent refused at its first call can still write why. A call is also refused when no transcript of the agent can be found, because a gate that cannot find what it checks has not seen the Read, and a gate that fails open there would stop gating in silence. The agent's transcript is `<the session transcript without .jsonl>/subagents/agent-<agent id>.jsonl`, the layout the status already reads; the agent's id is the one the latch files carry.

**What the check cannot see.** That the harness hands the hook the session transcript's path for an agent's call as it does for the main thread's is taken from the layout the rest of the family reads and is not measured here; the session's own folder is searched as a second route. A Read of the rules issued in the same message as another call counts for that call. And the file the agent reads is named for it by the CLAUDE.md it is handed, which this lesson's rule adds to.

**The general form.** A control that refuses an agent must leave it the one thing that lets the next send start from what it did, and a rule that every agent must follow is enforced at the agent's first call and not by the hope that it will read.
