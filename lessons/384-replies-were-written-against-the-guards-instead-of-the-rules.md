## 384 · Replies were written against the guards instead of the rules, a choice was lost under a report, and statuses went out as heartbeats while walks were failing

**Enforced by:** GATE noahjefferson:stop-guard.mjs — refuses a reply whose numbered options carry the recommended marker unless they open it, beside the slot and stop-declaration checks it already ran · GATE noahjefferson:report.mjs — every status prints each agent ended since the last one and each running agent's latest progress note, flagging a note that is missing or older than five minutes · GATE noahjefferson:plan-guard.mjs — lets an agent's own `TaskStop` through in plan mode, so plan mode put on while an agent runs cannot refuse that agent's cleanup

**Recorded 2026-10-02.** Three failures in one session, all with the same root: the session wrote to what would get past a check rather than to what the doctrine says, and where nothing checked, nothing held. A fourth, a gate's own, struck the same run and is recorded after them.

**Replies written against the guards.** The stop hook refused replies for shapes the doctrine already names. One opened four paragraphs in a row with a bolded lead-in, a slot §2 lists by name. Another carried a waiting phrase with no stop declaration, which §11c and §0e rule 6 both cover. Each rule was in the doctrine before the reply was written; the session found it out from the refusal. A guard that refuses a shape the doctrine names is doing the reading the session skipped, and its refusal is a defect of the reply, not feedback on it. The guards stay as the second line, and the first is writing the reply to the rules.

**A choice lost under a report.** A reply put its numbered options, one marked as recommended, beneath a long report, and the choice was missed. §2 already said a report ends in decisions, short and answerable; nothing said where in a reply an open choice stands, and nothing checked it. `stop-guard.mjs` now refuses a reply whose options carry the recommended marker unless that list opens the reply: at most two lines above its first item (a stop declaration and one lead-in), and no marked option in a later list. It finds a choice only by that marker, so a choice written as prose passes, and a numbered list with no marker is not read as a choice.

**Statuses as heartbeats.** During the release's verification, four of fifty-one walks had finished by 19:13 (California) and three of those four had failed, while the statuses kept arriving as heartbeats. Each was on time and each was stamped by `report.mjs`, which checks that a status was given and never what it says. A heartbeat tells the owner the session is alive and nothing about the work; a failing walk is a finding, and findings are acted on when they arrive, not left for an agent to report at the end of its run. Doctrine §0e rule 2 now says what a status carries: what changed and what it means, what the session did about it, and the time remaining read from the run, and one line when nothing is new. Every status `report.mjs` stamps now prints each agent that ended since the last one, with how it ended and its last entry, and each running agent's latest line from `progress/step-N.txt` in the session scratchpad, which every agent writes at each stage and at least every five minutes, flagged when it is missing or stale. The print puts what changed in front of the session at the moment the status is written. What the status then says is still the session's judgement, and no gate reads it.

**Plan mode refused an agent's cleanup.** While the release's verification agent was running its walks, the session put plan mode on to write an amendment to the plan, and `plan-guard.mjs`, which holds plan mode, refused that agent's `TaskStop` on a monitor the agent had started itself. An agent owns what it starts until it has confirmed it dead (§11d), and the gate left it no way to stop its own process. The walks stopped at 41 of 51 when the harness's two-hour limit on background commands ended the walk run and its scratch server. Stopping a process changes none of the owner's work, so `plan-guard.mjs` now lets an agent's own `TaskStop` through in plan mode. The main thread's `TaskStop` is not that one, and plan mode still refuses it.

**The general form.** A check catches the shapes it was written for, after the reply is written. A session that writes to the checks learns the rules one refusal at a time and passes everything nobody wrote a check for, which is where the choice and the statuses went. Read the rule, write to it, and let the guard find nothing.
