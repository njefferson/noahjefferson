## 455 · A plan written to a file an earlier plan used started with the earlier plan's steps done, because the gates keyed step ends on the path alone

**Enforced by:** GATE hub:session-guards.test.mjs — with two approvals of one plan path in one session, an agent sent for step 1 before the later approval is not an end of the later plan's step 1, an agent sent after it is, the approval time is the marker's `approvedAt` and else its own time, an agent whose start cannot be read is kept, and a report file last written before the approval is not read for Found lines; three plants (the time read, the filter on agents, the filter on report files) each turn the case red

**Recorded 2026-11-02.** The harness names the same plan file for every plan of a session. Lesson 442 made the list of step ends drop an agent whose prompt names another plan, which is no help when the next plan has the same name: the pointer, the status, the review gate, the judgement gate, the stop guard's steps-left check and the status page all read the earlier plan's hand-backs as the new plan's steps 1 and 2. The review of the plan before this one found six hand-backs counted that way, and the first plan's report files were overwritten by the second plan's agents for the same step numbers.

**What is done now.** The one reader of step ends, `stepEnds` in `report.mjs`, also asks when the agent began and keeps it only when that is not before the plan's approval. The approval time is read from the marker: `approvedAt`, which `approved-plan-guard.mjs` writes as the time of the approved exit (the owner's exit in the app, a button approval recovered from the transcript) or as the marker's own time for the tool's approval, and keeps through an amendment; a marker without it is read by its own `at`. A plan approved again after plan mode gets a new marker and so a new time. An agent whose start time cannot be read is kept, as the review gate keeps it, because dropping it would hide a real hand-back on an unreadable file. `foundLines` takes the same time and does not read a report file last written before it.

**What the change leaves.** A running agent of an earlier approval is still listed as running, since a running agent holds no step. The progress and report files are still named by step number alone, so a later plan's agent can overwrite an earlier plan's file; this plan avoided it by numbering its steps from 10, and the fix is in the agent rules, which change only as the last step of a plan with no plan in force after it.

**The general form.** A key that is shared by everything of one kind in a session cannot tell two uses of it apart; the thing that differs between the uses, here the moment of approval, has to be part of the key.
