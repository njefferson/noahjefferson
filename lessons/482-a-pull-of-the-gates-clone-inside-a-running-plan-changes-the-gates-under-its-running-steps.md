## 482 · A pull of the gates' clone inside a running plan changes the gates under its running steps

**Enforced by:** JUDGEMENT — the clone at the hub path every gate runs from is pulled before a plan's other steps or as the close's last act, and never by a step that runs beside steps that write files

**Smell:** a plan's take-up step runs beside its build steps and ends by pulling the clone the gates run from.

**Recorded 2026-11-09.** Measured on 9 November, California time.

**What happened.** The second writing of the infrared colour panel's plan ran its take-up beside its model, surface and test-page steps. The take-up's last act, ordered by its seeded text, pulled the clone to the hub's newest main at 10:41, and the plan fence in that commit holds an agent off every file of a Files line worded read only. The plan named each repository's changed files and then its unchanged ones on one line, so from that minute no file of the app or the hub could be written: the surface was refused at its tenth edit and the test page at its first, and the plan went back through plan mode for a third writing. The plan check that had passed the plan had run from the clone as it stood before the pull.

**What was wrong.** The gates are the rules the running steps are held to, and a step that changes them changes those rules under the others. The plan was approved under one set of rules and run under another.

**The test.** Find the step whose Do pulls the clone: it runs before the plan's other steps or it is the close's last act, with nothing beside it that writes files.

**The general form.** The rules a run is judged by are fixed for the run, and a newer set is taken up between runs.
