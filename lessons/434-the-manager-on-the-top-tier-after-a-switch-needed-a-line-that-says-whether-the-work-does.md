## 434 · The manager on the top tier after a switch needed a line that says whether the work does

**Enforced by:** GATE hub:session-guards.test.mjs — the case that reads the serving model from the model field of the newest main-thread reply and never from a key inside a tool's input, calls an id top-tier when it carries fable or mythos, has the status print name the model, and has the stop guard refuse the first reply under an approval marker after the serving model changes to a top-tier id unless its first line names the tier and says whether the work needs it, once for each change and with the words to use, with plants in report.mjs and stop-guard.mjs for every part that must fail it

Measured on 28 October. The manager's turns ran on the top tier for four hours of execution after a switch. The main thread only sends agents and checks their results, which the doctrine's section 11b says needs no more than a lesser tier. The session never said so, and the statement that the tier was not needed reached the record only after the work was over.

The rule was already written in the doctrine. What was missing was a place in the reply where a switch to the top tier had to be accounted for, so that the account arrives at the moment the tier changes and not after it has run for hours.
