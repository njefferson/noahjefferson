## 469 · The environment's git stop hook forced forty-two turns, and each one re-read the whole context at the main thread's tier

**Enforced by:** JUDGEMENT — a plan's Cost names the turns its push design will cause, because the cloud environment's git stop hook turns every uncommitted change and every unpushed commit into a turn of the main thread; and the fix of the hook belongs to the harness

**Smell:** a plan that holds its commits for one push at the end of a long run; an identity or a trailer that makes commits read as unverified; a plan whose Cost section is missing or does not mention pushes

**Recorded 2026-11-02.** Measured between 20:38 on 31 October and 16:35 on 1 November California time: the environment's own git check sent a stop-hook message forty-two times, for uncommitted changes while an agent worked, for commits shown as unverified while the commit identity of lesson 465 stood, and for unpushed local commits while a plan held its one push for its end. Each forced a turn whose whole content was one sentence saying the work was the agent's, and each such turn re-read between three and nine tenths of a million cached tokens. The main thread never committed for an agent, which was right.

**Why it is not gated here.** The hook is wired from the environment's launcher settings, outside any repository. A way for a repository to quiet it while an agent of the session runs is a change to the harness and is queued with that reason (Q-HUB-125). What this repository can do is price it: the Cost section the plan gate now asks for (lesson 458) states the pushes, and a design with one push at the end states the turns that costs.

**The general form.** A check outside the repository that fires on a state the plan chose is a cost of the plan's design, and a plan that does not name it has not priced itself.
