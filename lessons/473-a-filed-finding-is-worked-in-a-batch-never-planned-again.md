## 473 · A filed finding carries its judgement and is worked in a batch printed from the record, never planned again one at a time

**Enforced by:** GATE hub:plan-seed.mjs — `--batch` reads the program and the found folder, takes every open finding of the session's repository, groups the findings by the file each names, and prints a plan with a take-up step, one step per group that lands its own commit, and a close step; the print is held by cases and plants in session-guards.test.mjs

**Recorded 2026-11-06.** Measured on 5 November, California time, in one session.

**What happened.** The next ranked open item was worked as a plan of its own: one plan on the top tier, eleven agents, seven of them reviews, and two pushes for one hub item whose fix its found file already stated. The program held 308 items, of which 235 were hub findings each filed with its cause and its fix, and eighteen were app items that wait on their app's own session. The one-item print named the next ranked item, and that item belonged to a repository the session did not hold.

**What was wrong.** The rank mixes items of different sizes and repositories, and every item paid the ceremony built for a large one. A finding's judgement was made when it was filed, and it was made again each time the item was taken up, once to plan it and once to review the plan.

**The test.** Open findings of the session's repository are printed as one batch grouped by the file each fix lives in, taken up on the remote first so no second session plans them, one landed commit for each group; the button is pressed once for the batch, and an item of another repository is passed over and counted.

**The general form.** Work whose judgement is already written down is printed from the record in the shape of the work, so the ceremony is paid once for a batch and not once for each item.
