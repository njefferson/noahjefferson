## 395 · The approval priced every edit alike, a correction held every start alike, and no agent read a move before it went

**Enforced by:** GATE hub:hook-dispatch.mjs — `reviewGate` refuses a step of a plan with a review step unless a review that began after everything it judges has cleared it (ON-AIM ROUTE-CLEAR naming that step as next, read from the reviewer's own transcript); `correctionLifts` lets the review step and a step cleared after the message was typed through a correction; `ownerHolds` and `holdsIn` read a message that carries the whole word stop anywhere in it and ends with no go-word, and hold the main thread and every agent until a go-word
**Enforced by:** GATE hub:approved-plan-guard.mjs — the marker records the hashes of Goals, Asked, Files and Commands; a Write, Edit or MultiEdit on the approved plan by the main thread passes only when those four are unchanged in the text it would leave, and `--amend` re-reads the real file before it moves the marker's hash
**Enforced by:** GATE hub:session-guards.test.mjs — each behaviour above and its refusal, each watched failing with its plant first

**Recorded 2026-10-12.** Three controls in the manager's gates priced unlike things alike, and a fourth thing had no control at all.

**What the code did.** The approval marker held one hash, of the whole plan file, so an edit to a step, which changes how approved work is done, ended in the owner's button exactly as an edit to the files or commands the plan may touch did. A correction from the owner held every start on the main thread until the next go-word, so a message about one step froze every other step of an approved plan. A stop word stopped agents only while its message was still queued; once it was delivered nothing held them. And the next move was chosen by the main thread from its own reading of the hand-backs, with no agent that had written none of the work reading that move against the owner's aim and against the guards' own code before it went.

**What each looked like from inside.** Each priced one thing right and another wrong, and each was a rule that was right as written. Stopping a wrong plan was the expensive path, so a plan that needed one more step was amended in the main thread's head and run; freezing on every correction made the owner's corrections cost the whole plan; and a move that no one else had read was found wrong by the agent that ran it.

**The fix separates what the owner approved from how it is done.** Goals, Asked, Files and Commands are held by a hash recorded at approval, and an edit to any of them voids it. Steps and Order may be amended without coming back, and the amended step is cleared by a fresh review before it goes, because the plan's last write makes every earlier review stale. A correction holds new starts but lets the review and the step a review cleared go on, and the review must have begun after the message was typed, so it read the correction. One word, the whole word stop anywhere in a message that ends with no go-word, holds all of it, agents included, until a go-word. The first build took the word only as a message's first word; halt messages put it second, so that build would have stopped nothing for them.

**The general form.** A control that makes the cheap, correct action cost as much as the dangerous one gets routed around, or leaves the work stopped. Name what the owner chose, hold that by something a session cannot argue with, and let everything else move once an independent read has cleared it.
