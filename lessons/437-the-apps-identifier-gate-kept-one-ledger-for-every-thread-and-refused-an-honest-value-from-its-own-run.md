## 437 · The app's identifier gate kept one ledger for every thread and refused an honest value printed in the calling thread's own run, so each thread now has a ledger of its own, a print the harness saved passes by its path, and a figure in exponent form passes as a number

**Enforced by:** GATE Jefferson-Photography-Studio:.claude/hooks/ident-guard.mjs — the guard, which refuses a run of seven or more hex characters in a call that no tool result of the calling thread printed; it reads the thread's own ledger first and the shared one for what is still missing, `savedPrintRoots` and `withoutSavedPrints` pass a path under the harness's tool-results folder, and `hexTokens` drops a figure in exponent form
**Enforced by:** GATE Jefferson-Photography-Studio:.claude/hooks/ledger.mjs — `threadKey` and `threadLedgerPath`, one ledger file for each thread beside the shared one, to which each result is appended

**Recorded 2026-10-29.** Measured on 28 October in the app's hooks, which are not a hub gate and are cited here because the hub plans' rules lean on them (Q-HUB-6). The guard stops a session from writing an identifier it never saw printed, and it remembers what was printed in a ledger: one file for the main thread and every agent, capped near four megabytes, trimmed from the front. An agent used a commit's short id that its own git log had printed in the same run, and the guard refused it, because the shared ledger had grown past its cap with other threads' results and the value had scrolled off; the refusal latched the agent and cost a send (Found 225.1). Any thread's results pushed any other thread's earlier print off the same file: a status print, a review's reads, a flood from a sibling (Found 228.19, and the app's Q-JPS-20 and Q-JPS-143). After a compaction the main thread read the compaction hook's saved print before any tool result had printed its path, and the guard refused the read; the refusal latched, and the read the guard's own remedy allows was held until a message arrived (Found 0.14, Q-HUB-56). Two smaller refusals sat beside these: a path that exists on disk, and a figure in exponent form whose letter e joined the digits before it into one run (Q-JPS-144, Q-JPS-145, Q-JPS-146).

**What is done now.** In the app's step 230, landed on staging in the plan's step 231.
- A ledger for each thread beside the shared one, keyed by the agent id the hook payload carries and by main for the main thread. Each result is appended to the shared file and to the thread's own, each in its own try so one failing does not stop the other. The guard reads the thread's own file first and the shared file only for what is still missing, so a value another thread printed stays usable by this one and a value this thread printed is no longer pushed off by the others. The cap is unchanged.
- The rejected shape, written into the guard's header: reading the thread's transcript when the shared ledger misses. It would parse many megabytes for one lookup, it depends on the transcript's layout, and the transcript holds the session's own words beside the tool results, so a value the session produced could vouch for itself.
- A path under the session's tool-results folder, beside the transcript or above a subagent's, passes when the file is there and has no dot or dot-dot segment; a hex run beside it in the same call is still checked. The harness named these files, so the session could not have invented the name.
- A figure of digits, then e or E, then one to three digits, or digits and e followed by a signed exponent of one to three digits, passes as a number. A longer exponent, an f, a second e or a letter after the e still read as hex.
- The refusal's closing sentence names both ledgers and says a value read long enough ago to have scrolled off the thread's own is refused although it was honest.

**The excuse is that a window must end somewhere.** A cap is needed, and the cap was set when one thread was imagined. A check that asks whether a value was seen has to ask it of the thread that is asking, with a record that only that thread's prints can shorten.

**What the change cannot see.** A thread that itself prints more than the cap still loses its oldest print. A path that exists on disk outside the tool-results folder is still held to the ledgers (Found 0.27, with the app's Q-JPS-144 and Q-JPS-145 in their general form). The exponent exception lets about one random run of seven characters in a hundred through, computed and not measured. The per-thread files are left in the temp folder at the end of a session, one for each thread. No test of the guard is committed: the readings were taken by a scratch runner that drove the real hook files as child processes, once against a copy of the hooks taken before the edit and once against the working copy, and the guard carries no self-test flag of its own (Found 0.28). That a subagent's PostToolUse payload carries its agent id was not seen in a live payload, and a command that exits non-zero may never reach the ledger.

**The general form.** A memory that a gate consults has to be the memory of the thread that is asking, and a window onto what was read has to be longer than the work of the one who reads through it.
