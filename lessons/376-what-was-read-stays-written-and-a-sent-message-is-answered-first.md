## 376 · What was read stays written, and a message already sent is answered before the next tool call

**Enforced by:** GATE noahjefferson:keep-info-guard.mjs — run by `hook-dispatch.mjs` on every PreToolUse, it refuses a Bash command that makes a git commit when the commit's Markdown changes add a sentence that takes a particular source back (the three markings it looks for are listed at the top of the file) alongside how it was fetched, in that sentence or one beside it in the same paragraph, or drop a web domain the file named before; one finding is lifted only by a message from the owner in that session that names the source and asks for its removal in the same clause · GATE noahjefferson:pending-guard.mjs — first among the family guards, it refuses every main-thread tool call while a message from the owner sits enqueued and undelivered, and prints it verbatim; a pending message opening with STOP refuses subagents' calls as well · GATE noahjefferson:compact-recall.mjs — on SessionStart after a compaction, `hook-dispatch.mjs` prints the owner's messages since the previous compaction, verbatim, before the tool census and before any repo's brief · GATE noahjefferson:session-guards.test.mjs — twenty-two cases, including the six real withdrawals as fixtures, and twenty-four plants, each taking one check out and seen failing its case.

**Smell:** a commit message saying a reading no longer counts because of the identity a request was made in; a confirmed tally that goes down while no page changed; a list of tools that loses a name in a documentation commit; a long run of tool calls with a message from the owner waiting behind it; a plan proposal refused for being a repeat of a refused proposal.

**Recorded 2026-10-01.** Four failures in one day, each one a rule that already existed in a file and had nothing behind it at the point where it broke.

**1. Information was taken back because of how it had been fetched.** Two documentation commits in Jefferson-Photography-Studio, `57e9f0d` and `e3facbd`, added six sentences across four files (decisions 015, 069 and 085, and IR-SCIENCE.md) that took readings back, or reduced a source to its name, because the request that read them had been made in a browser's identity. Lightroom's Flat-Field Correction was dropped from a list of tools that divide per channel, Adobe's statement that shading can carry a colour cast went with it, and a confirmed tally went from 24 to 23. Every gate was green, because no gate asked whether a commit takes information back.

- **The rule underneath.** A page an ordinary person can read in a normal browser is information however it was fetched. When the method was wrong, the method is fixed and the way it was fetched is recorded as a fact; the reading stays. §374 refuses a request made in another identity; it never asked for a reading to be undone, and treating it as if it did is the failure here.
- **Restored** in Jefferson-Photography-Studio `bcea5f8`, from the parent commits' text, keeping the two factual corrections those commits made (helpx.adobe.com answering 200 to plain curl; Kept Light replacing a search snippet in 084).
- **Measured against history before it was trusted.** Run over every Markdown commit reachable in the two repositories' clones, 542 in Jefferson-Photography-Studio and 200 in the hub, the withdrawal check flags exactly those six sentences and nothing else. The domain check flags seven older commits that dropped a domain from a file. Three of those domains are now named nowhere in Jefferson-Photography-Studio: gregbenzphotography.com (a Lightroom masking page cited in decision 042 before a rewrite), eleken.co and blog.robsheaphotography.com.

**2. A message already sent waited behind tool calls.** The transcript records each message from the owner the moment it is sent, as a `queue-operation` with `operation: "enqueue"` and the message as `content`. It reaches the session later, as the next turn's prompt or as a `queued_command` attachment between tool calls, and the queue logs a `dequeue` (carrying no content) or a `remove` (carrying it) when it lets go. Until then the session cannot see it, and the longest waits are during long runs of tool calls: exactly when an instruction that changes the work is most expensive to miss.

- **Why the guard matches by text and counts as well.** A `dequeue` names nothing, and the queue takes by priority rather than in order, so the log alone cannot say which message left. A message is matched to its delivery by its words; the queue's size is kept from the counts, and when every enqueue has been dequeued or removed nothing is pending, whatever the matching found. A slash command is delivered as something other than its own words, and a guard waiting on its text would refuse forever.
- **A queue entry from an earlier process is never waited on.** `hook-dispatch.mjs` records each SessionStart that is not a compaction, and the guard ignores queue entries older than it.

**3. A compaction keeps a paraphrase.** The summary a compaction writes is the session's account of what it was told. The transcript still holds every message verbatim, so they are printed first, and where the summary differs, the messages are right.

**4. Two guards deadlocked plan approval.** A rejected `ExitPlanMode` came back as an error, `reply-guard.mjs` recorded it as a failed call, and its repeat rule refused the next `ExitPlanMode` until the error was read with `node reply-guard.mjs --read call:ID`, which `plan-guard.mjs` refused because plan mode allows no `node`. A plan could not be proposed again. Now plan mode's own two tools are never recorded as failures, an old ledger entry for one does not hold the next, and plan mode allows exactly one plain reading command for this hub's `reply-guard.mjs`, with nothing chained to it.

**What the guards cannot see.** The keep-info guard reads Markdown only, judges a sentence by its words (a withdrawal phrased without any of them passes), and sees a commit made by a Bash command, not by another tool. The pending guard reads the last 16 MB of the transcript, so a queue entry older than that is not counted, and a hook that is not installed refuses nothing: these run only where `hook-dispatch.mjs --install` has wired them (§370).
