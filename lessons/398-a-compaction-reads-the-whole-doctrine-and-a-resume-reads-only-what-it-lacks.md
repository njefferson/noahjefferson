## 398 · The doctrine read after a compaction was cut to a quarter that dropped the rules past section 2, and a resume owed a read it often held, so a compaction reads the whole file and a resume reads only what it lacks

**Enforced by:** GATE hub:session-guards.test.mjs — cases for a startup, a clear and a compaction making every line due, a resume after a whole read since the last compaction owing nothing, a resume after a part read owing every line, a resume after a whole read made only before the last compaction owing every line, and a resume holding only the text as it stands, each with plants that take one check out and must fail it

**Recorded 2026-10-14.** The doctrine is read to carry the rules the owner wrote across the point where a compaction replaces the conversation with a summary, word for word, because a summary is a paraphrase written by the thing the rules govern (§383). Two things in the gate cut that bridge. The owner questioned why a read of part of the file was ever enough, and chose the remedy below: the whole file after every compaction, no read after a resume while the whole current text is already in the session, and the gate changed to require exactly that.

**The bound cut the bridge for every section past section 2.** Lesson 385 limited the read after a compaction or a resume to the lines from the heading of §0 up to the heading of §3, lines 15 to 654 of 2494 when it was written, about a quarter of the file. Its reason was the share of a fresh context that the reload took, and its measurement was sound. What it did not weigh was where the rules sit. Accessibility (§4), honesty (§5), verification (§6), release discipline (§7), the privacy posture (§9b), the standing facts about the environment (§11), the credit (§11b), the approved plan as standing authority (§11c), processes (§11d), debugging (§14) and the services the apps depend on (§15) all come after section 2. After a compaction the session met each of them only as a line of the CLAUDE.md index, which is itself a paraphrase, so for those sections a summary stood where the file used to be, which is the failure §383 was written to end.

**A resume owed a read it often held.** The gate treated a resume as a compaction: it wrote the due marker again and asked for the bounded range without looking at what the resumed conversation held. A resume keeps the conversation as it was, so a session that had read the whole file was told to read a quarter of it again, and a session that had read part of it was told the same. Nothing counted what the conversation already held, so every resume owed a read, whether the session held the whole file, a part or none. The harness fires resumes for sessions nobody left (§387 counted four in one day), and each cost two reads before the turn's first call.

**What the gate does now.** A startup, a clear and a compaction make every line due, as a startup always did. A resume makes every line due unless the Read results on the live clone's DOCTRINE.md in the session's transcript, since its last compaction (or since the start of the transcript where there has been none), cover every line of the file as it stands now. For a resume the count is the file's present length as the harness counts it, and a result recorded with another total counts for nothing; a read made before the last compaction counts for nothing, because the compaction replaced it with a summary; and a file whose lines cannot be counted is due in full. The line printed at SessionStart begins DOCTRINE HELD and gives the count where nothing is due, and begins DOCTRINE DUE naming every line and their number where something is; the refusal names the same lines. The marker is still written for a resume, held or not, because the brief reads its source to print the lessons as a count.

**What the first version got wrong, and how it was found.** It counted the lines of text and compared them with the total each Read result records, and its cases passed, because they were written with the same count. Run against the session's own transcript before it landed, it found every real result stale: the live clone's file holds 2549 lines of text and every one of the sixteen results recorded 2550, the empty text after the final newline being the last line the harness numbers. A guard that finds every real result stale refuses for ever, and the cases could not have said so. The count is now the one the harness records; it is compared with a result's total only for a resume, where a wrong answer costs one more read, and never in the gate that clears a start, where it would cost a session its hands. The cases write their fixtures with a final newline and its extra line, a plant takes that count out, and the smoke run reads the real results in place and must find the doctrine held.

**What stays bounded.** The owner's messages after a compaction and the lessons' titles, as §385 set them. Only the doctrine's clause moved.

**What the check cannot see.** It counts lines and not text, so a change that keeps the doctrine's length between a read and a resume is not seen. It reads the last 16 MB of the transcript, so a whole read older than that is not seen and the resume owes the read again, which errs toward reading. It can count only what the transcript it is given holds. And it costs what the owner chose: a compaction now brings back the whole file, about two and a half thousand lines, which is the share §385 measured and bounded.

**The general form.** A bound on a read that exists to carry rules word for word has to be measured against where the rules are, not against how much of the file there is; and a gate that asks whether a read was made has to ask what the session holds, not which event fired.
