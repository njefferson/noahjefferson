## 374 · A reply that declines says why and how to ask; a session that files it as an obstacle goes around it and never reads it

**Enforced by:** GATE noahjefferson:reply-guard.mjs — run by `hook-dispatch.mjs` for the main thread and every subagent; like every family guard, a crash of it lets reads through, WebFetch among them. The next request to a host whose reply at 400 or above has not been read is refused, with the reply's own words quoted back — except a request that only reads that reply in full as curl itself (headers shown, nothing discarded, an `Accept` allowed, no data sent) — until `--read` records words present in that reply's own text and a route the reply allows, or a lone honest request is answered below 400. A reply captured among other output — with curl's `-w`, a second URL, a `file:` URL, a trace or options from a file — must first be read on its own, and a refusal loaded with `--seed` must be read again before any reading counts. A refusal binds its own host, `www.` folded; another service under the same domain answers for itself. A request in another identity toward a host that declined a script is refused outright, whatever was read: a user-agent flag in any spelling curl, wget and aria2c accept (alone, in a cluster, with its value attached, abbreviated, `--expand-…`, wget's `-e user_agent=` with or without separators), a header ending `-Agent:` or a browser's header, an option or header built at run time, options or headers read from a file the guard cannot see (`-K`, `--config`, `-H @file`), a client configuration that sets a user-agent or a `HOME`, `CURL_HOME`, `WGETRC` or `SYSTEM_WGETRC` pointing at another one, a browser's name, a browser run or driven, or a browser tool. A web client counts where a command runs it — in program position, behind wrappers such as `timeout`, `sudo`, `xargs` and `find -exec` — and every string a program runs is opened: what a shell is given with `-c`, `<<<`, a pipe or a heredoc (a heredoc piped from `cat` into a shell included), what `eval`, `env -S` and `script -c` run, a command waiting in a variable, a script written and run in the same line, and an interpreter's `-c`, `-e`, `--eval` or `-p` code, awk's program and a heredoc an interpreter reads, as code, in which only what a call runs is opened (`system(`, `execSync(`, `subprocess.run([…])`), four strings deep. In program text a host is taken only from a request call's URL argument, with comments taken out. A heredoc nothing runs, a commit message, a search pattern, a data table and a printed line are not requests. A status is read only where a reply can start, a client's own error wording only from that client, and a page the fetch tool answered is never parsed for one. A reading is one plain `node` command, refused if it carries a `$`, a backtick, a redirect or an extra word; the ledger cannot be written by a command that names it. An unchanged repeat of a failed call is refused until its error is read; an error or a reply of a few words is read by quoting all of it, and an interrupt or a hook's refusal is not a failure. `reply-guard.test.mjs` feeds it recorded payloads, and its `--plants` mode takes sixty-one of its checks out of a copy, one at a time, and sees a case fail for each. · CHECKLIST research-brief — write into every research brief that each refused host is reported with the reply's own words (body and instruction headers) and the route taken, and have that workflow's checker hold each entry to the agent's tool output.

**Smell:** a research note that lists hosts by status code with nothing of what each reply said; a retry that differs from the refused request only in the identity it presents; a second tool asked for what the first was refused.

**Recorded 2026-10-01.** One research pass for Jefferson-Photography-Studio's record 069, and the passes beside it, met five declining replies and read none of them as instructions.

- **pixinsight.com answered curl with 406.** Its body said that no appropriate representation of the resource could be found. RFC 9110 §15.5.7 defines a 406 as the resource having no representation acceptable according to the negotiation header fields the request sent, and §12.1 adds that a server may also select on parts of the User-Agent field. The honest answer is those fields, sent as curl: `Accept`, `Accept-Language`, `Accept-Encoding`. A checking agent instead retried in a browser's identity and read the site's documentation index that way, and its verdict in the research notes rested on that read. Asked again on 2026-10-01 as curl with an honest Accept, the site still answered 406, naming nothing it could serve.
- **www.sciencedirect.com's 403 carried `tdm-reservation: 1` and a `tdm-policy` link**, the publisher's published route for machine reading. Both were printed in the session's own probe, and neither was followed.
- **journals.ametsoc.org's CloudFront page, ResearchGate's page and IEEE's 418** were each recorded as a status. What each page said was not acted on, though one of them said the refusal was temporary.

**The rule already existed.** The hub's CLAUDE.md said a refusal is an instruction and a refusal naming its remedy is the instruction given twice, and Jefferson-Photography-Studio's said to suspect the instrument first. Nothing enforced either where a subagent would meet it, and the research agents were where the disguised request was made. The failure under all five was the same: a reply was read as an obstacle when it was an answer.

**What the gate cannot see.** A request whose URL is held in a program's variable rather than written into the request call, or read from a file, or built at run time; a request whose host is passed as an option rather than in a URL (`http.client.HTTPSConnection('host')`, `https.get({hostname})`); a request through a library it does not recognise (it knows `fetch`, Node's `http`/`https` modules, `undici`, `got`, `node-fetch`, `axios`, Python's `requests`, `urllib.request`, `urllib3`, `httpx`, `http.client` and `aiohttp`, Perl's LWP, PHP's `file_get_contents` of a URL, the command-line clients and the common browser drivers — not `git` over HTTP or anything else); a user-agent assembled at run time inside a program; strings nested more than four deep; a URL embedded in another service's URL, which binds only the outer host; and a ledger reached by a path that never names it. The research-brief checklist covers these, because it asks for the reply's words rather than for the request.

**How it was made.** Six scope checks each broke the version before. The first found a clustered `-sA`. The second found an attached `-sAbot`, `--user-a` and `bash -c`. The third found stacked wrappers, a scheme-less host, a `$( … )` riding inside a reading, an edited ledger and a one-line error that could never be read. The fourth found configuration redirected through `HOME`, options built from braces, browser tools, `sort -o` on the ledger and `--said` taken from an `echo`. The fifth found `$'\x2dA'`, `xargs`, shell functions, `node --eval`, awk, httpie, padded wget commands, and forged readings through curl's `-w` and through a seed. The sixth found a heredoc piped from `cat` into bash, subprocess argument lists, a script written and run in one line, a POST passing as a full read, three more forged readings, and a seeded refusal a later honest answer could never clear. The fourth, fifth and sixth also found it refusing honest work: heredoc commit messages and notes, localhost harnesses with a declined host in a comment, `grep -e curl`, 200 pages that quote a status, and a printed line naming curl. Then every tool call of the session that built it, 11 087 of them, was replayed through it with each refusing host on record. The replay found a refusal binding a whole domain (a 503 from patents.google.com refused the owner's photographs from drive.usercontent.google.com), the ledger rule refusing whole lines that only listed it, and short replies such as `404: Not Found` that could never be read. Run again after the sixth round, it found the guard refusing its own test scripts: a program's whole text had been opened as if any word in it might run, and a list of search words naming `exec(` read as a call. After those were fixed, every call it refused was a request to a host that had refused, or a test of the guard holding such a request as a string. Each form is now a test case, and the plants each remove one check.

**What it costs.** A program that holds, as a string, a call that runs a client toward a refusing host is refused as if it ran it, because the guard reads code without parsing its language; in practice that is a test of this guard. It runs once that host's reply has been read, and never while the string also changes the request's identity. Every status at 400 and above is recorded, so a 404 from a site the session is working on, its own staging included, needs one reading before the next request to it. Every non-zero exit is a failed call, and an edit does not lift the repeat rule: a test run again unchanged after a fix, a `grep` that found nothing, and a poll of a server that is still starting each need one `--read call:ID` quoting the error.

**A wiring note.** `hook-dispatch.mjs --install` now wires `PostToolUseFailure` too, but an event added to the user-level settings is not known to fire in the session that adds it. So failed calls are also caught up from the transcript tail on every `PreToolUse`, which needs no new event, and a hook's own refusal is never counted as a failure. Declining replies met before the gate ran can be loaded with `--seed` from an extraction of the transcripts; a seed adds refusals only, never a reading.

**What would close it further.** A research checker in each sibling repo that refuses an output whose refused hosts carry no words of their replies. Jefferson-Photography-Studio's research briefs live in session workflow scripts, not in the repository, so the requirement rides in the brief each time; it has no file of its own to gate.
