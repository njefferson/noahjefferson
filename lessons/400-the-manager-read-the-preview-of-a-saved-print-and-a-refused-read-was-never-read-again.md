## 400 · The manager read the preview of a saved print because the print, the science file and the decision records lay outside its record, and a read that was refused was never read again

**Enforced by:** GATE hub:session-guards.test.mjs — the case for the record list (the session's own saved tool results, IR-SCIENCE.md and the .md files directly in docs/decisions of any repository, and nothing of another session, a folder inside docs/decisions, another file type or an app's source) and the case for a refused read of the record (recorded for a refusal by a hook and for a failed Read, named in the status until a Read has returned, held by the reads gate without a latch, cleared by a Read and not by a failed one, dropped when the file is gone, never recorded for an agent or for a path outside the record), each with plants that take one check out and must fail it

**Recorded 2026-10-18.** A status print of about 120 KB reached the main thread as a preview of about 2 KB, with the whole text saved by the harness in the session's tool-results folder. The manager fence passes a read only of the record, and that folder was not on the list, so the manager worked from the preview. The same fence kept the science file and the decision records of the apps from the manager, though they are what a plan is judged against. The record therefore covers those files, on three conditions that are part of the rule: the list adds no risk (it holds no application source and nothing of another session), it gives no free rein (a path outside the list stays refused), and the reads made are watched for stacked errors (the status prints every read since the last status and every refused read still open).

**What was wrong underneath the list.** A refused read left nothing behind. The fence refused a call, the latch or a waiting message or a status falling due held the next one, and a read that a hook turned away, or that the harness failed because the file was too long, was simply not made. Nothing recorded that the manager had wanted that file and not had it, so the next step went on the strength of what was missing. This is the same shape as a held call that is not printed again (§376): a refusal that leaves no trace is a read that is silently dropped.

**What the gates do now.** The record list gains the session's own saved tool results (the folder and what is below it, for this session's id and no other), each repository's IR-SCIENCE.md, and the .md files directly in docs/decisions with the folder itself; a sub folder, another file type and the app's source stay outside. A Read of a file of the record that a hook refused, or that failed, is written to a per-session record (`noteRefusedReadCall`); a file that does not exist is not recorded, because nothing could clear it, and neither is a refused read outside the record, which is the fence doing its work, or an agent's. The status prints the main thread's reads since the last status as a count and their paths, and names each refused read that no Read has since returned (`readsBlock`, `unreadRefusals`). The dispatch gate's reads check (`readsGate`) sends no step, a Workflow included, while one is named, and does not latch: reading the file is the way out, and a latch would wait on the owner for nothing. A later Read that returned clears it; a Read that failed does not.

**What the check cannot see.** A read counts as made when any Read of that exact path returned without an error, whatever range it covered, so a part of a long file clears it; the doctrine and the state page have their own whole-file gates and this one does not repeat them. A read made through Grep or Bash is not recorded. And the list is exactly the one named in the paragraph above: nothing here widens it to an app's source.

**The general form.** When a session may not read something, the refusal is an instruction to ask for the access, and the access, once given, goes on the list the gate reads from. When a read is refused for any other reason, the refusal is recorded where the next decision can see it, because a decision made on a file that was not read is made on the preview.
