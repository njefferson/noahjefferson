## 454 · The sweep kept every branch from before the history rewrite, because its merge test cannot run without a common base

**Enforced by:** GATE hub:.github/workflows/branch-sweep.yml — a `claude/*` branch whose merge test exits 128 and which has no merge base with main is removable only when the tree id of its tip is the tree id of a commit in main's whole history, read from a list of every tree id main reaches; any other such branch is kept and printed with its tip tree and the count of commits main lacks; a clone that is still shallow stops the run

**Recorded 2026-11-02.** The hub's last session branch stayed on the remote through two sweep runs, each logging a merge test that exited 128 with 357 commits main lacks. The history rewrite of 2026-09-18 gave every commit a new id, so every branch cut before it shares no history with main, and the merge test needs a common base to compute anything. The sweep treated the exit as a verdict that the branch held work main lacked, which it did not say: it said the question could not be asked that way. A branch that could never be judged could never be removed.

**What is done now.** The sweep keeps its test for a branch that shares history with main, unchanged. For a branch with no merge base it asks a different question that the missing base does not block: is the tree of the branch's tip a tree some commit of main holds. A rewrite of messages keeps trees, so a branch whose work was merged before the rewrite matches, and a branch carrying unmerged work does not. Removing it then loses no byte, since every file the tip holds is in main's history. The lease at the judged id, the dry run by default, the `claude/*` scope and main as the only base are unchanged.

**What the change leaves.** The test says the content is held somewhere in main's history, not that main's current tree still has it; a branch whose tip matched an old tree of main is removable even if main later changed those files, because the content is still reachable from main. A branch holding work main lacks stays, with the reason in the log, and whether that work is wanted is then the owner's choice.

**The general form.** A test that exits with an error for a whole class of input is not a verdict on the class. When every branch of one age fails the same way, the defect is in the instrument, and the cure is the nearest question the input can answer, stated so that the answer still means no work is lost.
