## 479 · A test page that prints what each stage costs on the device answered in one press what container renders at a minute and a half each could not

**Enforced by:** JUDGEMENT — a question about what a stage costs or how a photograph reads on the reader's device is answered by building the measurement into the app's test page, and a session does not run renders in a container to answer it

**Smell:** a session plans several container renders to learn a number that depends on the device's own graphics, memory or decoder; the sign is a run measured in minutes per render whose result the owner then has to doubt because the container is not the device.

**Recorded 2026-11-08.** Measured on 8 November, California time, in the session of the infrared app.

**What happened.** The infrared app's separation measure was first approached by rendering the photograph in the container, each render taking about a minute and a half, and the numbers could not be trusted for a tablet. The app's test page was then made to read the photograph on the device and print what each stage cost and what it measured, with the median and the individual runs, and one press on the device answered what the container renders had not, in seconds, with the app's version in the copied block.

**What was wrong.** The measurement was put where it was convenient to run and not where the answer is true. The doctrine's rule for the test page says a container answers a different question from the device, and the work went on as though it did not.

**The test.** Where a number depends on the device, name the stage, build one press on the test page that runs it three times and prints the median with the spread, and read the pasted block. A container render is a check of the code path and never the figure.

**The general form.** The test page is the instrument for any question the device alone can answer; a session that reaches for container runs first pays a minute and a half for each answer that is not the answer.
