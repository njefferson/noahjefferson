## 418 · A call reworded after a refusal lost a night

**Enforced by:** JUDGEMENT

**Smell:** a second publish or command for the same end sent straight after a refusal with only its words changed; a line saying nothing more is needed while a call is still open; an unattended run sent after a call that is not on the plan's named list.

**Recorded 2026-10-20.** On 2026-10-19 the reply guard refused a publish of the status page at 22:06 California. At 22:21 the main thread sent the same publish with only its description changed, which the reply guard keys by the page and not by the call's words, so the second refusal latched the main thread. Every send was refused from then until the owner's next message, and the run approved at 22:02, with an estimate of six to nine hours, never started. Minutes earlier the main thread had said that nothing more was needed for the night, before its last call had returned.

**What is done now.** Three moves, each already a rule and each missed that evening. A call reworded after a refusal is the second route the doctrine forbids; the refusal is the answer and the route waits on the owner. A statement that nothing more is needed is made only after the turn's last call has returned. A run meant to go unattended is sent before any call outside the plan's named list, the page's publish included.

**What the check cannot see.** No gate holds the three yet, so this lesson is a judgement and not a refusal. Whether a latch should reach an unattended run at all is the owner's open design choice, queued as Q-HUB-45 in `NOTES.md`.

**The general form.** A refusal that latches is a closed route for the whole run, and a reworded call is the same route under a new name. The cheapest way past a refusal is to stop, say what was refused, and let the owner's next message open the route again.
